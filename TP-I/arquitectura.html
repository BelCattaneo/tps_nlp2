Zoom: el Block

Un Block es un decoder pre-norm con dos sub-bloques (attn y FF), cada uno envuelto en un residual.

Estructura de un Block. Los residuales (líneas azules) llevan la entrada intacta y la suman después de cada sub-bloque.

Detalle: la norma va antes de attn y ff (pre-norm), no después. Es la variante de GPT-2 en adelante. Y las sumas son al x sin normalizar, no al normalizado — el LayerNorm alimenta a attn/ff pero no a la suma residual.

Zoom: MultiHeadAttention

Todas las cabezas se procesan en paralelo dentro de un solo kernel de GPU. Nunca hay un loop de Python sobre n_head.

Flujo interno de MultiHeadAttention.forward. En verde las operaciones específicas de atención, en azul las lineales generales, en violeta el KV-cache (opcional, sólo en inferencia).

Zoom: FeedForward

Una MLP simple: expande al 4× y contrae de vuelta, con ReLU en el medio. Actúa por token, sin comunicación entre posiciones.

Feed-forward por token. Sin cabezas, sin máscara, sin tokens hablando entre sí.

Las tres cosas que suenan bien pero se rompen en silencio

El TP marca estas tres como "detalles fáciles de tener mal en silencio". Vale tenerlas presentes.

1. La forma del retorno depende de los flags, no del cache.
TinyGPT.forward decide qué devuelve (logits, o tupla) mirando use_cache y return_weights, no si kv_cache es None. Si dependiera del cache, el primer paso de generación (que llega sin cache) nunca podría inicializar uno, y use_cache=True sería un no-op silencioso. Ver líneas 336–343 de tinygpt.py.
2. La máscara causal y los positional embeddings se desplazan por el largo del cache.
Con cache, el token nuevo NO está en la posición 0 — está en la posición past_len. Los positional embeddings se generan con torch.arange(past_len, past_len + T), y la máscara se slice como self.tril[past:T_k, :T_k]. Sin ese offset, cada nuevo token con cache pensaría que es el primer token de la secuencia. Ver líneas 225 y 318.
3. Todas las cabezas se computan en un solo matmul batcheado.
No hay loop de Python sobre n_head. La proyección KQV es un único Linear(64, 192), y la atención opera con (B, n_head, T, head_dim) — donde n_head queda como dimensión de batch para el matmul. A esta escala el tiempo lo domina el lanzamiento de kernels, no la aritmética, así que un loop sobre 4 módulos costaría varias veces el paso entero. Ver líneas 194, 205, 222.

Recorridos de shape (referencia rápida)

Entrenamiento

idx                          (64, 32)
 → token_emb + pos_emb        (64, 32, 64)
 → Block 0                    (64, 32, 64)
 → Block 1                    (64, 32, 64)
 → ln_f                       (64, 32, 64)
 → head                       (64, 32, 65)     ← logits
 → return logits              tensor pelado (no tupla)

Paso 1 de generación (prompt "hola", sin cache aún)

idx                          (1, 4)
 → token_emb + pos_emb        (1, 4, 64)     pos = [0, 1, 2, 3]
 → Block 0 (use_cache=True)   (1, 4, 64) + cache_0 de shape (2, 1, 4, 4, 16)
 → Block 1 (use_cache=True)   (1, 4, 64) + cache_1 de shape (2, 1, 4, 4, 16)
 → ln_f                       (1, 4, 64)
 → head                       (1, 4, 65)     ← se toma logits[:, -1, :] para muestrear
 → return (logits, [cache_0, cache_1])

Paso 2 de generación (token nuevo, con cache)

idx                          (1, 1)     ← sólo el token nuevo
 → token_emb + pos_emb        (1, 1, 64)     pos = [4]  (past_len = 4)
 → Block 0 (con cache_0)      (1, 1, 64) + cache_0 actualizado (2, 1, 4, 5, 16)
   dentro de la atn:
     q                        (1, 4, 1, 16)     ← sólo el token nuevo
     k, v (post-concat)       (1, 4, 5, 16)     ← 4 viejos + 1 nuevo
     wei = q · K^T / √16      (1, 4, 1, 5)
     wei · V                  (1, 4, 1, 16)
 → Block 1 (con cache_1)      (1, 1, 64) + cache_1 actualizado
 → head                       (1, 1, 65)
 → return (logits, [cache_0', cache_1'])

Notas de implementación

  • Pre-norm, no post-norm. LayerNorm va antes de attn y ff. Es la convención de GPT-2 en adelante — más estable de entrenar.
  • Sólo self-attention, no cross-attention. Al ser decoder-only, no hay encoder al que atender. Un Block tiene un solo bloque de atención (self, causal).
  • Positional embeddings aprendibles, tamaño fijo. Nada de RoPE ni sinusoidales — una tabla de block_size = 32 filas que se entrena junto con el resto.
  • Weight tying. head.weight es literalmente el mismo tensor que token_emb.weight. Ahorra vocab_size × n_embd parámetros y funciona bien.
  • Máscara como buffer, no como parámetro. self.tril viaja con el modelo (state_dict, to(device)) pero no se entrena. Registrada con register_buffer.
  • Retorno con forma variable. Cuando ambos flags son False, retorna tensor pelado (esperado por Trainer). Caso contrario, tupla con las salidas solicitadas.
