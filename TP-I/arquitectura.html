El diagrama principal sigue la convención visual del paper original (Vaswani et al. 2017), adaptada a un modelo decoder-only (sin encoder ni cross-attention) y pre-norm (LayerNorm antes de cada sub-bloque, no después).

Diagrama principal

Embedding LayerNorm Multi-Head Attention Feed Forward Linear

Flujo del modelo, de abajo hacia arriba. El bloque punteado marcado Nx se repite n_layer = 2 veces. Los residuales (flechas curvas a la derecha) devuelven la entrada intacta hasta después de cada sub-bloque.

Diferencia con el paper. El paper original dibuja "Add & Norm" después de cada sub-bloque (post-norm). TinyGPT usa pre-norm (variante GPT-2 en adelante): el LayerNorm va antes del sub-bloque y el residual se suma después. Es más estable de entrenar. Ver Block.forward, líneas 268–274 de tinygpt.py.

Las tres cosas que suenan bien pero se rompen en silencio

El TP marca estas tres como "detalles fáciles de tener mal en silencio". Vale tenerlas presentes.

1. La forma del retorno depende de los flags, no del cache.
TinyGPT.forward decide qué devuelve (logits, o tupla) mirando use_cache y return_weights, no si kv_cache es None. Si dependiera del cache, el primer paso de generación (que llega sin cache) nunca podría inicializar uno, y use_cache=True sería un no-op silencioso. Ver líneas 336–343 de tinygpt.py.
2. La máscara causal y los positional embeddings se desplazan por el largo del cache.
Con cache, el token nuevo NO está en la posición 0 — está en la posición past_len. Los positional embeddings se generan con torch.arange(past_len, past_len + T), y la máscara se slice como self.tril[past:T_k, :T_k]. Sin ese offset, cada nuevo token con cache pensaría que es el primer token. Ver líneas 225 y 318.
3. Todas las cabezas se computan en un solo matmul batcheado.
No hay loop de Python sobre n_head. La proyección KQV es un único Linear(64, 192), y la atención opera con (B, n_head, T, head_dim) — donde n_head queda como dimensión de batch. A esta escala el tiempo lo domina el lanzamiento de kernels, así que un loop sobre 4 módulos costaría varias veces el paso entero. Ver líneas 194, 205, 222.

Recorridos de shape (referencia rápida)

Entrenamiento

idx                          (64, 32)
 → token_emb + pos_emb        (64, 32, 64)
 → Block 0                    (64, 32, 64)
 → Block 1                    (64, 32, 64)
 → ln_f                       (64, 32, 64)
 → head                       (64, 32, 65)     ← logits
 → return logits              tensor pelado (no tupla)

Paso 1 de generación (prompt "hola", sin cache aún)

idx                          (1, 4)
 → token_emb + pos_emb        (1, 4, 64)     pos = [0, 1, 2, 3]
 → Block 0 (use_cache=True)   (1, 4, 64) + cache_0 de shape (2, 1, 4, 4, 16)
 → Block 1 (use_cache=True)   (1, 4, 64) + cache_1 de shape (2, 1, 4, 4, 16)
 → ln_f                       (1, 4, 64)
 → head                       (1, 4, 65)     ← se toma logits[:, -1, :] para muestrear
 → return (logits, [cache_0, cache_1])

Paso 2 de generación (token nuevo, con cache)

idx                          (1, 1)     ← sólo el token nuevo
 → token_emb + pos_emb        (1, 1, 64)     pos = [4]  (past_len = 4)
 → Block 0 (con cache_0)      (1, 1, 64) + cache_0 actualizado (2, 1, 4, 5, 16)
   dentro de la atn:
     q                        (1, 4, 1, 16)     ← sólo el token nuevo
     k, v (post-concat)       (1, 4, 5, 16)     ← 4 viejos + 1 nuevo
     wei = q · K^T / √16      (1, 4, 1, 5)
     wei · V                  (1, 4, 1, 16)
 → Block 1 (con cache_1)      (1, 1, 64) + cache_1 actualizado
 → head                       (1, 1, 65)
 → return (logits, [cache_0', cache_1'])

Notas de implementación

  • Pre-norm, no post-norm. LayerNorm va antes de attn y ff. Convención GPT-2 en adelante — más estable de entrenar.
  • Sólo self-attention, no cross-attention. Al ser decoder-only, no hay encoder al que atender. Un Block tiene un solo bloque de atención (self, causal).
  • Positional embeddings aprendibles, tamaño fijo. Nada de RoPE ni sinusoidales — una tabla de block_size = 32 filas que se entrena junto con el resto.
  • Weight tying. head.weight es literalmente el mismo tensor que token_emb.weight. Ahorra vocab_size × n_embd parámetros.
  • Máscara como buffer, no como parámetro. self.tril viaja con el modelo pero no se entrena. Registrada con register_buffer.
  • Retorno con forma variable. Cuando ambos flags son False, retorna tensor pelado (esperado por Trainer). Caso contrario, tupla.
